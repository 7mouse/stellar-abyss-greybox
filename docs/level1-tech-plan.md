# 第一关精细化技术方案（起程村 + 第 1 层）

Godot 4.7.2，渲染器用 Compatibility（Web 只能用这个，单线程导出，因为 GitHub Pages 发不了 COOP/COEP 头）。

## 1. 美术素材怎么接入
- **角色和怪物动画**：每个角色一张精灵图集，用 AnimatedSprite2D + SpriteFrames。按美术清单画 4 个朝向（正前、正后、右、右前 3/4），左边用镜像（flip_h），所以 8 个方向只需要画 4 个。
  - 动作名统一用 idle / move / attack_1..3 / dash / skill / hit / death，代码只认这些名字。
  - 攻击判定帧、音效帧用 AnimationPlayer 打关键帧（method track）。美术改了帧数，只需要动关键帧，不用改代码。
  - 每个实体只从一个固定路径读贴图（现在的占位也是这样放的），交图时直接覆盖。
- **地面（TileMap）**：用 TileMapLayer 分成几层：地面、装饰、遮挡（树冠、屋檐，主角走到后面时半透明）。
  - 地形边缘用 Godot 的 terrain 自动拼接。美术按 Godot 的 3×3 最小拼接集交图，每格 64×64，第 1 层大约需要 4 种地形。
  - 现在第 1 层的开放地图是程序生成的，接入后改成：生成器只输出地形编号，再由 TileMapLayer 去画。碰撞和寻路网格保持现在的做法。
  - 起程村是固定地图，直接手工摆 TileMap。
- **光照**：只用 CanvasModulate 做整体色调，加少量 PointLight2D（火把、撤离点、宝箱）。同屏光源 ≤ 8 个，不开阴影。Web 端阴影和法线贴图太贵，第一关不做。
- **粒子**：一律用 CPUParticles2D，不用 GPUParticles2D，因为 Compatibility 和 Web 下 GPU 粒子不稳定。
  - 每种特效做成单独场景，放进对象池复用，不在战斗中途新建。
  - 同屏粒子 ≤ 300 颗，单个特效 ≤ 40 颗。

## 2. 打击感怎么实现
统一放进一个 HitFeedback 模块。每个技能用一份 .tres 配参数，F1 里可调：
- **顿帧**：命中时停 50 到 80 ms。只停攻击者和被击者的动画，不停整个游戏（用 Engine.time_scale 会连 UI 一起卡）。
- **屏幕震动**：Camera2D 的 offset 做衰减抖动，轻攻击 2 到 4 像素，重攻击和层主 6 到 10 像素。设置里提供开关和强度滑条。
- **受击反馈**：被击者白闪约 80 ms（一个很小的 shader），加一小段击退位移，再在命中点放一个火花粒子、弹出伤害数字。
- **音效**：每个技能 2 到 3 个变体随机播，音高随机 ±5%。同一帧多次命中只播一次，免得声音叠成一团。
- **手柄**：命中时短震（Input.start_joy_vibration），设置里可以关掉。
- **输入手感**：攻击按键缓冲 150 ms；连段在动画后段有一个可以取消的窗口。
- 以后接入的小游戏判定沿用同一套反馈接口。

## 3. Web 导出性能预算
目标是中端笔记本浏览器上稳定 60 帧，即每帧 16.7 ms。
- **每帧时间**：脚本加物理 ≤ 5 ms，绘制 ≤ 8 ms，剩下的留给浏览器。
- **同屏数量**：清醒的敌人 ≤ 12 只，远处的继续休眠（现在已经这么做）；同屏精灵 ≤ 150 个，光源 ≤ 8 个，粒子 ≤ 300 颗。
- **贴图**：每张图集 ≤ 2048×2048，按屏幕上的显示大小出图，不放大量 4K 原图。不开 mipmap，因为在软件渲染上实测更慢。
- **包体**：首次加载的 .pck 加 wasm 压缩后 ≤ 40 MB，第一关的美术 ≤ 25 MB。音乐用 OGG，音效用短 WAV。
- **加载**：进入第 1 层时，生成加导航烘焙 ≤ 800 ms（现在约 110 ms）。
- **验收**：每次推送都跑网页检查，12 敌混战看 rAF 帧间隔的 p95。注意检查用的是无头浏览器加软件渲染，p95 会在 16.7 和 33.4 ms 之间跳，所以以多次结果为准；最好再找一台真机，用 Chrome 实测一次。

## 补充（按负责人口径）：骨骼动画、遮挡、水面、尺寸

### 骨骼动画：Skeleton2D 和 Spine 哪种更适合 Web
| | Godot 自带 Skeleton2D | Spine（spine-godot 运行时） |
| --- | --- | --- |
| Web 单线程导出 | 引擎自带，用官方导出模板就能导出，没有额外风险 | 要换成 Spine 官方的定制引擎，或者走 GDExtension 加 Web 动态链接模板。能不能在单线程导出下跑、跟不跟得上 Godot 4.7，要先做一次实测 |
| 费用 | 免费 | 美术要买 Spine 编辑器授权（Essential 或 Pro） |
| 美术工作流 | 在 Godot 编辑器里绑骨骼、刷权重、K 动画，工具比较粗糙 | Spine 编辑器很成熟，网格变形、IK、换皮都方便，导出 .skel 加图集 |
| 运行开销 | 每个角色是多个 Polygon2D 加 Bone2D，每个部件一次绘制 | 每个角色一个网格，绘制次数少，CPU 蒙皮 |

**建议：第一关用 Skeleton2D**，它对 Web 导出没有额外风险，也不用花钱。如果美术坚持要用 Spine，先花半天做一个 spine-godot 的 Web 单线程导出验证，跑通了再换。

**Skeleton2D 的接入做法**
- 美术把角色拆成部件 PNG（头、身体、四肢、配饰）交过来，每个部件附一张 PSD 或者带部件坐标的整图；单个角色的部件打成一张 ≤ 1024 的图集。
- 场景结构：Skeleton2D 下面挂 Bone2D 骨骼链；身体等需要弯曲的部件用带权重的 Polygon2D，其他部件就是普通 Sprite2D 挂在骨骼上。
- 动画用 AnimationPlayer K 骨骼的旋转和位移。动作名还是 idle / move / attack_1..3 / dash / skill / hit / death；判定帧和音效帧用 method track 打点，和之前的方案一致。
- 朝向：骨骼动画做正前、正后、右侧 3 套骨架，左边镜像。右前 3/4 先不单独做，用右侧那套顶上，以后需要再加。
- 动画由谁来 K 先要定：Godot 里的骨骼动画通常由程序或技术美术来做，美术主要交拆好的部件。这一点要美术设计确认。
- 预算：同屏骨骼角色 ≤ 13 个（主角加 12 只敌人），每个 ≤ 20 根骨骼、≤ 15 个部件。休眠的远处敌人停掉动画更新。

### 大树遮挡半透明
- 树冠和屋檐放在单独的遮挡层（Y 排序在角色上面）。
- 每棵树挂一个 Area2D；主角进入后，树冠的透明度用补间动画在 0.15 秒内降到约 0.4，离开后再恢复。
- 只有挡住主角的那棵变透明，不用 shader，开销基本为零。

### 水面 shader
- 水面是 TileMapLayer 里单独的一层，挂一个 CanvasItem shader：两层法线噪声贴图做 UV 扰动加波纹，边缘泡沫用一张遮罩，画屏幕纹理会更贵，所以先不做反射和折射。
- Web 的 Compatibility 渲染器支持这种写法。片段计算控制在大约 10 次纹理采样以内；水面面积很大的场景，可以在设置里切到低画质（关掉扰动）。
